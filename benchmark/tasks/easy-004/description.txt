A small internal banner service needs one protected configuration value and should recover automatically if its only pod is deleted.

- Create a Namespace named `easy-restart-ns`.
- In namespace `easy-restart-ns`, create an Opaque Secret named `banner-secret` containing exactly one key, `BANNER`, with value `hello-restart`.
- Set Secret `banner-secret` to `immutable: true`.
- In namespace `easy-restart-ns`, create a Deployment named `restart-web` with exactly one replica and pod label `app=restart-web`. Its single container must be named `web`, use `busybox:1.36.1`, set environment variable `BANNER` from `banner-secret/BANNER` using `secretKeyRef`, and run `sh -c "mkdir -p /work && printf 'ready\n' > /work/index.html && httpd -f -p 8080 -h /work"`. Expose TCP container port 8080 and use a TCP readiness probe on that port with `periodSeconds: 5`.
- In namespace `easy-restart-ns`, create a ClusterIP Service named `restart-svc` selecting `app=restart-web`, with TCP port 8080 targeting container port 8080. After the initial pod is Ready, an evaluator may delete that pod; a replacement with a different UID must become Ready within 60 seconds, and `restart-svc:8080` must then return exactly `ready` followed by a newline.
- In namespace `easy-restart-ns`, create a ResourceQuota named `restart-quota` whose hard limits are exactly `pods: "5"`, `services: "2"`, and `secrets: "3"`.
