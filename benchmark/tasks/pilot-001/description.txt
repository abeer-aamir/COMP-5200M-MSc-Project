I need an order-processing stack in Kubernetes. Keep the whole application in
one namespace called `order-system` (apart from the Namespace object itself),

The cache should be a StatefulSet called `cache`, with 2 replicas and pods
labelled `role=cache`. Give it a headless Service called `cache-headless` on TCP
6379. Each cache pod needs its own 1Gi `ReadWriteOnce` claim from a volume claim
template named `cache-data`, mounted at `/data`. The cache containers should

The API should be a Deployment called `api`, with 3 replicas labelled
`role=api`, using port 8080. It should serve a simple successful `/health`

`cache-0.cache-headless` and `cache-1.cache-headless` to resolve and answer on
6379 before the main container starts. In other words, do these checks through
normal pod DNS and network traffic, not by asking the Kubernetes API for the
StatefulSet status.

Create `api-config` with these exact entries and expose it to the API as
environment variables:

```
APP_MODE=production
CACHE_HOST=cache-headless
CACHE_PORT=6379
```

CACHE_HOST=cache-headless
