A finance support team needs a bounded calculation job and a service identity whose access to the job input can be revoked and restored cleanly.

- Create a Namespace named `medium-batch-ns`.
- In namespace `medium-batch-ns`, create a ConfigMap named `batch-input` containing exactly `VALUE=17` and `FACTOR=3`.
- In namespace `medium-batch-ns`, create an Opaque Secret named `batch-mode` containing exactly one key, `OPERATION`, with value `multiply`.
- In namespace `medium-batch-ns`, create a ServiceAccount named `batch-runner` with `automountServiceAccountToken: true`.
- In namespace `medium-batch-ns`, create a Role named `batch-input-reader` containing exactly one rule: API group `""`, resource `configmaps`, resourceName `batch-input`, and verb `get`. It must grant no other API groups, resources, resource names, or verbs.
- In namespace `medium-batch-ns`, create a RoleBinding named `batch-input-reader-binding` that binds only ServiceAccount `batch-runner` to Role `batch-input-reader`. Authorization as `system:serviceaccount:medium-batch-ns:batch-runner` must allow `get` on ConfigMap `batch-input` and deny `list` on ConfigMaps. After an evaluator temporarily deletes this RoleBinding, `get` on `batch-input` must become denied within 15 seconds; after the evaluator reapplies the identical RoleBinding, `get` on `batch-input` must become allowed again within 15 seconds.
- In namespace `medium-batch-ns`, create a ResourceQuota named `batch-limits` whose hard limits are exactly `count/jobs.batch: "3"` and `pods: "6"`.
- In namespace `medium-batch-ns`, create a Job named `multiply-job` using ServiceAccount `batch-runner`. Its single container must be named `calculator`, use `busybox:1.36.1`, set `VALUE` and `FACTOR` from the matching keys in ConfigMap `batch-input`, set `OPERATION` from Secret `batch-mode` key `OPERATION` using `secretKeyRef`, and run `sh -c "test \"$OPERATION\" = multiply && result=$((VALUE * FACTOR)) && echo result=$result && test \"$result\" -eq 51"`. Set `restartPolicy: Never`, `backoffLimit: 1`, and `activeDeadlineSeconds: 60`. The Job must reach Complete within 60 seconds and its only pod must log exactly `result=51` followed by a newline.
- Configure Job `multiply-job` with `completions: 1`, `parallelism: 1`, `completionMode: NonIndexed`, and `ttlSecondsAfterFinished: 600`.
- Set Secret `batch-mode` to `immutable: true`.
