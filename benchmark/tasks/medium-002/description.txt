A finance support team needs a bounded calculation Job and a service identity whose access to the input can be revoked and restored cleanly. Put these resources in `medium-batch-ns`.

Create `batch-input` with exactly `VALUE=17` and `FACTOR=3`, and an immutable Opaque Secret named `batch-mode` whose only entry is `OPERATION=multiply`. The ServiceAccount `batch-runner` should explicitly enable automatic service-account token mounting. Give it a Role called `batch-input-reader` with exactly one core-API rule: `get` on the single ConfigMap named `batch-input`. Bind only `batch-runner` to that Role through `batch-input-reader-binding`; it must be able to get that object but not list ConfigMaps. An evaluator will temporarily remove the binding, at which point the get permission must become denied within 15 seconds, and reapplying the identical binding must restore it within another 15 seconds.

Run `multiply-job` using `batch-runner`. Its one container is named `calculator`, uses `busybox:1.36.1`, loads `VALUE` and `FACTOR` from their matching `batch-input` keys, and loads `OPERATION` from `batch-mode/OPERATION` using a `secretKeyRef`. Run `sh -c "test \"$OPERATION\" = multiply && result=$((VALUE * FACTOR)) && echo result=$result && test \"$result\" -eq 51"`. Use `restartPolicy: Never`, `backoffLimit: 1`, and `activeDeadlineSeconds: 60`. The Job should Complete within 60 seconds and its sole pod should log exactly `result=51` followed by a newline. Configure it for one completion and one parallel pod, `completionMode: NonIndexed`, and `ttlSecondsAfterFinished: 600`.

Add `batch-limits`, a ResourceQuota whose complete hard-limit set is exactly three batch Jobs and six pods.
