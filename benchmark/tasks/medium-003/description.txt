A small stateful registry needs stable per-replica storage and predictable recovery without exposing it to unrelated workloads. Keep the resources in `medium-stateful-ns`.

Put `PREFIX=registry` as the only key in ConfigMap `registry-prefix`, and put `SUFFIX=stable` as the only key in Opaque Secret `registry-suffix`. Create a headless Service named `registry-headless` with `clusterIP: None`, `publishNotReadyAddresses: false`, selector `app=registry`, and TCP port 8080 targeting a named port called `http`.

Run the registry as StatefulSet `registry`, tied to `registry-headless`, with two replicas and pod label `app=registry`. Its one container is also named `registry`, uses `busybox:1.36.1`, receives `PREFIX` from `registry-prefix/PREFIX` and `SUFFIX` from `registry-suffix/SUFFIX` through their respective key references, and exposes named TCP port `http` on 8080. Give each pod a claim from a volume claim template called `data`, requesting exactly 64Mi with `ReadWriteOnce`, mounted at `/data`. Start the container with `sh -c "if [ ! -f /data/index.html ]; then printf \"%s-%s-%s\\n\" \"$PREFIX\" \"$HOSTNAME\" \"$SUFFIX\" > /data/index.html; fi; httpd -f -p 8080 -h /data"` and use an HTTP readiness probe for `/` on named port `http` every five seconds. Both pods should be Ready within 90 seconds.

Run the pods as non-root UID and GID 1000 with `fsGroup: 1000`; disable privilege escalation, use a read-only container root filesystem, and drop all Linux capabilities. Retain claims when the StatefulSet is deleted or scaled down. Use `OrderedReady` pod management and RollingUpdate with partition zero. Add a PodDisruptionBudget named `registry-pdb` selecting the registry pods with `minAvailable: 1`.

NetworkPolicy `registry-ingress` should select the registry pods and allow TCP 8080 only from same-namespace pods labelled `access=registry`, denying all other ingress to the selected pods.

The storage recovery must work, not just look correct in the manifest. An evaluator will write `oracle-marker` to `/data/oracle-marker` on `registry-0` and delete that pod. A different-UID `registry-0` must become Ready within 90 seconds with the marker unchanged, and `registry-headless` must return to exactly two Ready endpoint addresses within the same time.
