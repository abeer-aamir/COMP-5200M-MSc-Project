A development team needs a hardened read-only diagnostics page and a scheduled check that remains disabled until an operator enables it.

- Create a Namespace named `easy-diagnostics-ns`.
- In namespace `easy-diagnostics-ns`, create a ConfigMap named `diagnostics-content` containing exactly one key, `index.html`, with value `diagnostics-ready` followed by a newline.
- In namespace `easy-diagnostics-ns`, create a Deployment named `diagnostics-web` with exactly one replica and pod label `app=diagnostics-web`. Its single container must be named `web`, use `busybox:1.36.1`, run `httpd -f -p 8080 -h /www`, expose named TCP port `http` on 8080, mount the complete `diagnostics-content` ConfigMap read-only at `/www`, and use a TCP readiness probe on port `http` with `periodSeconds: 5`.
- Harden the `diagnostics-web` pod by setting pod-level `runAsNonRoot: true` and `runAsUser: 1000`, and container-level `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, and `capabilities.drop: ["ALL"]`.
- In namespace `easy-diagnostics-ns`, create a ClusterIP Service named `diagnostics-svc` selecting `app=diagnostics-web`, with TCP port 80 targeting the named port `http`. It must obtain a Ready endpoint within 60 seconds, after which an in-namespace test pod must receive exactly `diagnostics-ready` followed by a newline from `http://diagnostics-svc`.
- In namespace `easy-diagnostics-ns`, create a CronJob named `diagnostics-check` with schedule `*/10 * * * *`, `suspend: true`, and `concurrencyPolicy: Forbid`. Its job template must use `busybox:1.36.1`, run `sh -c "echo diagnostics-suspended"`, and set `restartPolicy: Never`.
