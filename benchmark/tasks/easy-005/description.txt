A development team needs a hardened read-only diagnostics page and a scheduled check that stays disabled until an operator enables it. Put all of this in `easy-diagnostics-ns`.

The page content belongs in a ConfigMap called `diagnostics-content`. It should contain only `index.html`, with `diagnostics-ready` followed by a newline. Create a one-replica Deployment named `diagnostics-web` with pod label `app=diagnostics-web`. Its single container is `web`, uses `busybox:1.36.1`, mounts the complete ConfigMap read-only at `/www`, runs `httpd -f -p 8080 -h /www`, and exposes TCP 8080 as a named port called `http`. Use a TCP readiness probe on that named port every five seconds.

Run the pod as non-root UID 1000. At pod level set `runAsNonRoot: true` and `runAsUser: 1000`; on the container disable privilege escalation, make the root filesystem read-only, and drop all Linux capabilities.

Expose the page through a ClusterIP Service named `diagnostics-svc`, selecting `app=diagnostics-web`, with TCP port 80 targeting the named `http` port. It should obtain a Ready endpoint within 60 seconds, and an in-namespace test pod must then receive exactly `diagnostics-ready` followed by a newline from `http://diagnostics-svc`.

Finally, create a suspended CronJob called `diagnostics-check`, scheduled for `*/10 * * * *` with `Forbid` concurrency. Its job template should use `busybox:1.36.1`, run `sh -c "echo diagnostics-suspended"`, and set `restartPolicy: Never`.
