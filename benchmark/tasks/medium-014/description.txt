Please set up a two-tier internal view in `medium-view-ns`. One pod serves a source page and two mirror pods continuously copy that page into their own response. The mirrors should track source changes without rolling, and they should stop advertising readiness if the source Service disappears.

The source page lives in mutable ConfigMap `view-source-page`, containing only `index.html=source=v1\n`. Put `TOKEN=mirror-ok` as the only value in immutable Opaque Secret `view-key`.

Deployment `view-source` has one replica labelled `app=view-source` and `component=source`. Its single `busybox:1.36.1` container mounts the page at `/srv`, serves it on named TCP port `source-http` at 8080, probes `/` every five seconds and does not mount an API token. It should be Ready within 90 seconds. Expose it through ClusterIP Service `view-source-svc`, port 8080 to `source-http`, selecting `app=view-source`.

Deployment `view-mirror` has two replicas labelled `app=view-mirror` and `component=mirror`. Its one `busybox:1.36.1` container reads `TOKEN` from `view-key` using a `secretKeyRef` and has an `emptyDir` at `/www`. Every two seconds, make a request to `view-source-svc` bounded to five seconds. Only when the token is `mirror-ok` and the request succeeds should `/www/index.html` contain `view:<source body>`; otherwise remove the output. Serve `/www` on named TCP port `view-http` at 8081 and probe `/` every five seconds with failure threshold two. Disable API-token mounting and use RollingUpdate with zero unavailable, one surge, five ready seconds and a 150-second progress deadline. Both mirrors should be Ready within 150 seconds.

ClusterIP Service `view-svc` selects `app=view-mirror` and exposes port 80 to `view-http`. A client labelled `access=view` must receive exactly `view:source=v1\n`. Default-deny ingress to both tiers. Allow source TCP 8080 only from pods labelled `component=mirror` or `access=view`, and mirror TCP 8081 only from `access=view`; unlabelled clients must reach neither Service.

Run source and mirror containers as non-root UID/GID 1000 with `fsGroup: 1000`, no privilege escalation, read-only root filesystems and all capabilities dropped. Only the mirror's `/www` is writable.

When the source page changes to `source=v2\n`, the Ready source and both Ready mirrors must expose their exact v2 bodies within 150 seconds without changing either Deployment generation or any pod UID. Restore v1 within another 150 seconds, again without rollout. Then save and delete `view-source-svc`: both mirrors must become NotReady and `view-svc` must lose all Ready endpoints within 60 seconds. Restoring that exact Service must recover one source endpoint, two mirror endpoints and the exact v1 view body within 150 seconds. Restoration should always be attempted, including after an earlier failed assertion.
