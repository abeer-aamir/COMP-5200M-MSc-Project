A platform team needs a small hardened health endpoint and a paused scheduled checker that can be exercised safely before it is enabled.

- Create a Namespace named `medium-check-ns`.
- In namespace `medium-check-ns`, create a ConfigMap named `check-content` containing exactly one key, `index.html`, with value `check-ready` followed by a newline.
- In namespace `medium-check-ns`, create a Deployment named `check-web` with exactly two replicas and pod label `app=check-web`. Its single container must be named `web`, use `busybox:1.36.1`, mount the complete ConfigMap `check-content` read-only at `/www`, run `httpd -f -p 8080 -h /www`, expose named TCP container port `http` on 8080, and use an HTTP readiness probe on path `/` and named port `http` with `initialDelaySeconds: 2`, `periodSeconds: 5`, and `failureThreshold: 3`. Both replicas must become Ready within 60 seconds.
- In namespace `medium-check-ns`, create a ClusterIP Service named `check-svc` selecting `app=check-web`, with TCP port 80 targeting named port `http`. Once the Deployment is Ready, a permitted in-namespace client must receive exactly `check-ready` followed by a newline from `http://check-svc`.
- Harden every `check-web` pod with pod-level `runAsNonRoot: true`, `runAsUser: 1000`, `runAsGroup: 1000`, and `fsGroup: 1000`, and container-level `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, and `capabilities.drop: ["ALL"]`.
- In namespace `medium-check-ns`, create a NetworkPolicy named `check-ingress` selecting `app=check-web`. It must allow ingress on TCP 8080 only from pods in the same namespace labelled `access=checker`, with all other ingress to the selected pods denied.
- In namespace `medium-check-ns`, create a CronJob named `scheduled-check` with schedule `*/5 * * * *`, `suspend: true`, `concurrencyPolicy: Forbid`, `successfulJobsHistoryLimit: 1`, and `failedJobsHistoryLimit: 1`. Its pod template must have label `access=checker`, use one container named `checker` with image `busybox:1.36.1`, and run `sh -c "i=0; until body=$(wget -qO- http://check-svc); do i=$((i + 1)); [ \"$i\" -ge 10 ] && exit 1; sleep 2; done; test \"$body\" = check-ready && echo check-ok"` with `restartPolicy: Never`. When an evaluator creates one Job from this suspended CronJob, it must reach Complete within 60 seconds and its pod must log exactly `check-ok` followed by a newline.
- In namespace `medium-check-ns`, create a PodDisruptionBudget named `check-pdb` selecting `app=check-web` with `minAvailable: 1`.
- Configure Deployment `check-web` with `RollingUpdate` strategy, `maxUnavailable: 0`, `maxSurge: 1`, `minReadySeconds: 5`, `progressDeadlineSeconds: 90`, and `revisionHistoryLimit: 2`.
