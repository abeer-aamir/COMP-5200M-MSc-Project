We need a small release mirror for an internal team. The source and its downstream mirror should both stay honest about what they can actually serve, including when the source disappears temporarily. Put the whole setup in `hard-mirror-ns`.

Start with a mutable ConfigMap called `mirror-source` whose only data is `index.html` containing `release=v1` and a trailing newline. Add an immutable Opaque Secret named `mirror-key`; its only value is `TOKEN=mirror-ok`.

Run the source as Deployment `release-origin` with two `app=release-origin` replicas. Each pod has one `busybox:1.36.1` container named `origin`, mounts the full ConfigMap at `/source`, and serves it on named TCP port `origin-http` at 8080. Give it HTTP startup and readiness probes on `/` every five seconds, disable automatic service-account token mounting, and have both replicas Ready within 90 seconds. ClusterIP Service `release-origin-svc` should select those pods and expose TCP 8080 to the named port. A client labelled `role=mirror` should receive exactly `release=v1\n`.

The downstream Deployment is `release-mirror`, again with two replicas, labelled `app=release-mirror`. Its init container should make no more than 45 attempts, two seconds apart, for `release-origin-svc` to return exactly `release=v1`. The one main `busybox:1.36.1` container, `mirror`, reads `TOKEN` from the Secret through a `secretKeyRef` and has a writable `emptyDir` at `/www`. Every two seconds it should write `mirror:<origin body>` to `/www/index.html` only when the token is `mirror-ok` and the source request succeeds, removing that file otherwise, while httpd serves `/www` through named TCP port `mirror-http` at 8081. Probe `/` every five seconds with failure threshold two, disable its API token, and make both replicas Ready within 150 seconds. Service `release-mirror-svc` exposes port 80 to that named target; an `access=release` client should get exactly `mirror:release=v1\n`.

Run every origin, mirror and init container as non-root UID and GID 1000 with `fsGroup: 1000`, no privilege escalation, read-only root filesystems and all capabilities dropped. The mirror's `/www` emptyDir is the only writable location.

Use NetworkPolicies to default-deny ingress and egress for both applications. Origin TCP 8080 should be reachable only from `role=mirror` or `access=release`; mirror TCP 8081 only from `access=release`; and mirror egress only to origin TCP 8080 plus cluster DNS on UDP and TCP 53. An unlabelled client must reach neither Service. Add `release-origin-pdb` and `release-mirror-pdb`, each selecting its matching app with `minAvailable: 1` and no `maxUnavailable`.

Create a Job called `release-smoke`, labelled `access=release`, with one `busybox:1.36.1` container. It gets at most 60 attempts, two seconds apart, for `release-mirror-svc` to return exactly `mirror:release=v1`, then prints `release-smoke-ok`. Use `restartPolicy: Never`, no backoff, and a 150-second active deadline. It should Complete within 150 seconds and its log should be exactly `release-smoke-ok\n`.

Set container defaults in LimitRange `mirror-defaults` to requests of 20m CPU and 32Mi memory and limits of 200m CPU and 128Mi memory. ResourceQuota `mirror-quota` must have exactly these hard limits: 12 pods, four Services, three batch Jobs, 2 CPU and 1Gi memory in requests, and 4 CPU and 2Gi memory in limits.

I also need two reversible behaviours. Changing the ConfigMap page to `release=v2\n` must make both Ready origin pods serve that body and both Ready mirrors serve `mirror:release=v2\n` within 150 seconds, without changing either Deployment generation or any pod UID. Restoring v1 must converge in another 150 seconds without rollout. Separately, if an evaluator saves and deletes `release-origin-svc`, both mirrors should become NotReady and their Service should have no Ready endpoints inside 90 seconds. Recreating the exact source Service must restore two origin endpoints, two mirror endpoints and the original final response within 180 seconds; the evaluator will restore it even if the check fails.
