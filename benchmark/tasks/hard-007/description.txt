Please build a small retained shard service in `hard-shard-ns`. It has two stable members and a separate two-replica index which should only be Ready while it can verify both members.

Use a mutable ConfigMap `shard-prefix` containing only `PREFIX=shard`, and an immutable Opaque Secret `shard-signing` containing only `SIGN=signed`. The headless Service `shard-headless` needs `clusterIP: None`, `publishNotReadyAddresses: false`, selector `app=shard`, and TCP 8080 routed to named port `shard-http`.

StatefulSet `shard` has two replicas, `serviceName: shard-headless`, `OrderedReady` management, RollingUpdate partition zero, and Retain policies for claims on both scaling and deletion. Label its pods `app=shard` and `component=member`. An `initialize` init container writes `g1\n` to `/data/generation` only if the file is absent. The one main `busybox:1.36.1` container, `shard`, reads `SIGN` from the Secret, mounts the prefix at `/config` and its claim at `/data`, and every three seconds refreshes `/data/index.html` as `<PREFIX>-<HOSTNAME>-<SIGN>-<generation>\n` without removing other files. Serve it on named TCP port `shard-http` at 8080 and probe `/` every five seconds with failure threshold three. Disable API-token mounting and make both members Ready within 180 seconds. Each `data` claim requests exactly 64Mi with `ReadWriteOnce`.

ClusterIP Service `shard-svc` selects `app=shard` and exposes port 80 to `shard-http`. It should have exactly two Ready addresses; the stable headless names should serve `shard-shard-0-signed-g1\n` and `shard-shard-1-signed-g1\n`.

Deployment `shard-index` has two replicas labelled `app=shard-index` and `component=index`. Its one `busybox:1.36.1` container mounts the prefix read-only at `/config` and an `emptyDir` at `/www`. Every three seconds it fetches both stable member URLs and creates `/www/index.html` containing `<PREFIX>-ready=2\n` only while both exact current bodies match; otherwise it removes the file. Serve `/www` on named TCP port `index-http` at 8081, probe `/` every five seconds with failure threshold two, and disable the API token. Use RollingUpdate with no unavailable pods, one surge, five ready seconds and a 210-second progress deadline; both replicas should be Ready within 210 seconds. `shard-index-svc` exposes port 80 to the named port, and an `access=shard` client should get exactly `shard-ready=2\n`.

All member, init, index and audit containers run as non-root UID/GID 1000 with `fsGroup: 1000`, no privilege escalation, read-only root filesystems and all capabilities dropped. Only member claims and index `/www` may be writable.

Default-deny ingress and egress for member and index pods. Allow member TCP 8080 only from `component=index`, `role=shard-audit` or `access=shard`; index TCP 8081 only from `role=shard-audit` or `access=shard`; and index egress only to members on 8080 plus cluster DNS on UDP/TCP 53. Unlabelled clients should reach neither Service. Add `shard-pdb` and `shard-index-pdb`, each with `minAvailable: 1`, the matching app selector, and no `maxUnavailable`.

ResourceQuota `shard-quota` has exactly: 12 pods, three PVCs, 256Mi storage requests, four Services, three batch Jobs, two CronJobs, 2 CPU and 1Gi memory requests, and 4 CPU and 2Gi memory limits.

Add suspended CronJob `shard-audit`, scheduled `17 * * * *`, using `Forbid` concurrency and retaining one successful and one failed Job. Its pod label is `role=shard-audit`; the one hardened `busybox:1.36.1` container gets at most 90 attempts, two seconds apart, for `shard-index-svc` to return exactly `shard-ready=2`, then prints `shard-audit-ok`. Use `restartPolicy: Never` and a 210-second active deadline. A Job made from this template should Complete within 210 seconds and log exactly `shard-audit-ok\n`.

Two live changes matter. Changing `PREFIX` to `shard2` must update both exact member bodies and the index body within 180 seconds without changing either controller generation or any pod UID; restoring `shard` gets another 180 seconds and must also avoid rollout. Separately, if an evaluator writes `retained\n` to `/data/oracle-marker` on `shard-1` and deletes that pod, a different-UID `shard-1` must be Ready within 150 seconds with both the marker and generation unchanged. Both Services should return to two Ready endpoints and the exact index response within 210 seconds.
