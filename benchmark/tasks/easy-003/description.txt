A support team wants one service identity to have narrowly limited read access to a single settings object. Put the resources in a namespace called `easy-rbac-ns`.

Create an immutable ConfigMap named `audit-target` containing only `MODE=read-only`, and a ServiceAccount called `audit-reader`. The Role `audit-reader-role` should have exactly one rule: the core API group, resource `configmaps`, resource name `audit-target`, and verb `get`. It must not grant any other API groups, resources, resource names, or verbs.

Bind only the `audit-reader` ServiceAccount to that Role using `audit-reader-binding`. Authorization for `system:serviceaccount:easy-rbac-ns:audit-reader` to get `configmap/audit-target` in this namespace must initially return `yes`. An evaluator will temporarily delete the RoleBinding; the same authorization must become `no` within 15 seconds, then return to `yes` within another 15 seconds after the identical binding is reapplied.
