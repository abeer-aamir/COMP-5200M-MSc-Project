Build a two-input quorum page in `hard-quorum-ns`. The final view should only be Ready while both independently served inputs and its token agree.

Mutable ConfigMap `quorum-inputs` contains exactly `alpha=a1\n` and `beta=b1\n`; immutable Opaque Secret `quorum-key` contains only `TOKEN=quorum-ok`. Deploy two replicas each of `quorum-alpha` and `quorum-beta`, labelled with matching app and component values. Alpha mounts only its key as `/srv/index.html`, serves named `alpha-http` on 8080, and is exposed by `quorum-alpha-svc` on 8080. Beta does the same on named `beta-http`/8081 through `quorum-beta-svc`. Use one `busybox:1.36.1` container per pod, HTTP readiness, no API token, and make both pairs Ready in 120 seconds.

Deployment `quorum-view` has two replicas labelled `app=quorum-view` and `component=quorum`. Its one BusyBox container reads the Secret token and has emptyDir `/www`. Every two seconds it makes bounded requests to both input Services and writes `quorum=<alpha without newline>+<beta>` only while both bodies and the token are exact, removing output otherwise. Serve named `quorum-http` on 8082, probe every five seconds with failure threshold two, disable its API token, and use RollingUpdate with zero unavailable, one surge and five ready seconds. Both replicas should be Ready within 180 seconds. `quorum-svc` exposes port 80; `access=quorum` clients receive exactly `quorum=a1+b1\n`.

Run all containers as non-root UID/GID 1000 with `fsGroup: 1000`, no privilege escalation, read-only roots and all capabilities dropped; only quorum `/www` is writable. Default-deny all application ingress/egress. Each input is reachable only from `component=quorum` or `access=quorum`, the final view only from `access=quorum`, and quorum egress only to both inputs plus DNS UDP/TCP 53. Unlabelled clients reach none. Add one matching PDB per Deployment with `minAvailable: 1`. LimitRange `quorum-defaults` uses requests 20m CPU/32Mi and limits 200m CPU/128Mi; ResourceQuota `quorum-quota` has exactly 14 pods, five Services, 2 CPU/1Gi requests and 4 CPU/2Gi limits.

Changing alpha to `a2\n` must update alpha and both final pods to `quorum=a2+b1\n` within 150 seconds without generation or UID changes; restoration gets another 150 seconds. Replacing one Ready quorum pod after endpoint removal must permit twelve exact one-second calls and produce a new Ready UID within 90 seconds. Deleting the saved beta Service must make both quorum pods NotReady and remove final endpoints within 90 seconds while alpha remains Ready; exact restoration recovers endpoint counts 2/2/2 and the normal body within 180 seconds, with cleanup always restoring it.
