A small operations team needs an internal status page and a paused diagnostics schedule in its own Kubernetes namespace.

- Create a Namespace named `easy-status-ns`.
- In namespace `easy-status-ns`, create a Deployment named `status-web` with exactly one replica and pod label `app=status-web`. Its single container must be named `web`, use `busybox:1.36.1`, expose a named container port `http` on TCP 8080, and run `sh -c "mkdir -p /www && printf 'status=green\n' > /www/index.html && httpd -f -p 8080 -h /www"`. Give it a TCP readiness probe on the named port `http` with `periodSeconds: 5` and `failureThreshold: 3`; the pod must become Ready within 60 seconds.
- Configure `status-web` with Deployment strategy type `Recreate` and `revisionHistoryLimit: 1`.
- In namespace `easy-status-ns`, create a ClusterIP Service named `status-svc` selecting `app=status-web`, with TCP port 80 targeting the named port `http`. Once the pod is Ready, an in-namespace test pod labelled `access=status` must be able to fetch `http://status-svc` and receive exactly `status=green` followed by a newline.
- In namespace `easy-status-ns`, create a NetworkPolicy named `status-ingress` selecting `app=status-web`. It must allow ingress on TCP 8080 only from pods in the same namespace labelled `access=status`, with all other ingress to the selected pods denied.
- In namespace `easy-status-ns`, create a CronJob named `diagnostics-report` with schedule `0 * * * *`, `suspend: true`, and `concurrencyPolicy: Forbid`. Its job template must run `busybox:1.36.1` with `sh -c "echo diagnostics-ready"` and `restartPolicy: Never`.
