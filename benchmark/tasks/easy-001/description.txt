A small operations team needs an internal status page and a paused diagnostics schedule in its own Kubernetes namespace. Please keep everything in `easy-status-ns`.

The page should run as a Deployment called `status-web` with one replica and the pod label `app=status-web`. Its only container is named `web`, uses `busybox:1.36.1`, and exposes TCP 8080 as a named port called `http`. Start it with `sh -c "mkdir -p /www && printf 'status=green\n' > /www/index.html && httpd -f -p 8080 -h /www"`. Give it a TCP readiness probe on the named `http` port every five seconds with a failure threshold of three, and have the pod Ready within 60 seconds. The Deployment should use the `Recreate` strategy and retain one revision of history.

Put a normal ClusterIP Service named `status-svc` in front of the page. It should select `app=status-web` and expose TCP port 80 through the named `http` target. Once the pod is Ready, a client pod in the same namespace carrying `access=status` must receive exactly `status=green` followed by a newline from `http://status-svc`.

Restrict access with a NetworkPolicy called `status-ingress`. It should select the status pods and allow TCP 8080 only from same-namespace pods labelled `access=status`; all other ingress to those pods should be denied.

Also create a CronJob called `diagnostics-report`. Schedule it for `0 * * * *`, leave it suspended, and use `Forbid` concurrency. Its job template should use `busybox:1.36.1`, run `sh -c "echo diagnostics-ready"`, and set `restartPolicy: Never`.
