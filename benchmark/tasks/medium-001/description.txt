An internal operations portal needs configuration changes to appear without a rollout, while still remaining available through ordinary pod replacement. Keep the whole setup in `medium-portal-ns`.

Store the page in `portal-content`, a ConfigMap containing only `index.html=portal-version=v1\n`. Store `API_TOKEN=medium-token` as the only value in an Opaque Secret named `portal-token`, and mark that Secret immutable.

Run the portal as Deployment `portal-web` with exactly two replicas and pod label `app=portal-web`. Each pod has one container, `web`, using `busybox:1.36.1`. Load `API_TOKEN` from `portal-token/API_TOKEN` using a `secretKeyRef`, mount the complete `portal-content` ConfigMap read-only at `/www`, and run `sh -c "test \"$API_TOKEN\" = medium-token && httpd -f -p 8080 -h /www"`. Expose named TCP port `http` on 8080 and use an HTTP readiness probe for `/` on that port every five seconds with a failure threshold of three. Both pods should be Ready within 60 seconds. Run them as non-root UID and GID 1000 with `fsGroup: 1000`; disable privilege escalation, make the container root filesystem read-only, and drop all capabilities.

Use RollingUpdate with no unavailable pods and one surge pod, plus `minReadySeconds: 5`, `progressDeadlineSeconds: 90`, and `revisionHistoryLimit: 2`. Put a PodDisruptionBudget named `portal-pdb` over the portal pods with `minAvailable: 1`.

Expose the portal with ClusterIP Service `portal-svc`, port 80 to the named `http` target. A same-namespace client labelled `access=portal` should receive exactly `portal-version=v1` and a newline from `http://portal-svc`. If one Ready portal pod is deleted and has left the Service's Ready endpoint set, ten requests at one-second intervals must all succeed through the remaining endpoint, and a replacement with a different UID must become Ready within 60 seconds.

Restrict ingress with NetworkPolicy `portal-ingress`, selecting the portal pods and allowing TCP 8080 only from same-namespace pods labelled `access=portal`; deny all other ingress to those pods.

The ConfigMap must remain a live projected mount. An evaluator will change `portal-content/index.html` to `portal-version=v2\n`; every Ready portal pod must serve that exact new body within 120 seconds without changing the Deployment generation or any pod UID. After the original value is restored, every Ready pod must serve `portal-version=v1\n` again within another 120 seconds, still without a rollout.
