We need a small persistent audit store in Kubernetes, all under a namespace called `hard-audit-ns`. This is for a single-node Kubernetes 1.35 Kind cluster with no workload internet, so use `busybox:1.36.1` throughout and ordinary built-in resources only.

The store has a ConfigMap named `audit-prefix` containing only `PREFIX=audit` and an Opaque Secret named `audit-suffix` containing only `SUFFIX=verified`. Both objects should be immutable. Give the audit pods a headless Service called `audit-headless`, with `clusterIP: None`, no publishing of unready addresses, and TCP port 8080 targeting a named `http` port. I also need a regular ClusterIP Service called `audit-svc`, selecting the same `app=audit-store` pods and exposing port 80 to `http`.

Run the data service as StatefulSet `audit-store`, tied to `audit-headless`, with exactly two replicas and pod label `app=audit-store`. Its single container is `store`, takes `PREFIX` from `audit-prefix/PREFIX` and `SUFFIX` from `audit-suffix/SUFFIX` via a Secret key reference, and has a per-pod claim template named `data`. Each claim should request exactly 64Mi with `ReadWriteOnce`, mounted at `/data`. Use `sh -c "if [ ! -f /data/index.html ]; then printf \"%s-%s-%s\\n\" \"$PREFIX\" \"$HOSTNAME\" \"$SUFFIX\" > /data/index.html; fi; httpd -f -p 8080 -h /data"`, expose named TCP port `http` on 8080, and check readiness with HTTP `/` on that port every five seconds. Both replicas need to be Ready within 90 seconds.

Please make the pod security fairly strict: non-root UID and GID 1000, `fsGroup: 1000`, no privilege escalation, a read-only root filesystem, and all Linux capabilities dropped. Retain its PVCs on both StatefulSet deletion and scale-down. Use `OrderedReady` pod management and RollingUpdate with partition zero.

Only approved audit clients should reach this service. A NetworkPolicy named `audit-ingress` should select `app=audit-store` and allow TCP 8080 only from same-namespace pods labelled `access=audit`; everything else coming into those pods should be denied.

The inspection identity is ServiceAccount `audit-inspector`. Create Role `audit-observer` with exactly two rules: one permits `get` and `list` for core Pods, and the other permits only `get` for core ConfigMap `audit-prefix`. Bind only `audit-inspector` to it using RoleBinding `audit-observer-binding`. It must not be able to read Secrets, write resources, list ConfigMaps, or operate outside this namespace.

Create a Job named `audit-inspection` using that ServiceAccount and label its pod `access=audit`. Run the pod as non-root UID/GID 1000 with `fsGroup: 1000`; its one `busybox:1.36.1` container, `inspector`, should have privilege escalation disabled, a read-only root filesystem, and all capabilities dropped. It should query `audit-store-0.audit-headless:8080` and `audit-store-1.audit-headless:8080` with up to 30 two-second attempts per address, require the exact bodies `audit-audit-store-0-verified` and `audit-audit-store-1-verified`, and print `audit-inspection-ok` only after both match. Give it `restartPolicy: Never`, `backoffLimit: 0`, and `activeDeadlineSeconds: 150`. The Job should Complete within 150 seconds and its only pod should log exactly that success line.

We need the identity and persistence to be testable too. Authorization as `system:serviceaccount:hard-audit-ns:audit-inspector` should allow listing Pods and getting `audit-prefix`, while denying Secret reads and ConfigMap lists. If the RoleBinding is temporarily deleted, the allowed checks should turn to `no` within 15 seconds; putting the identical binding back should restore them to `yes` within another 15 seconds.

For storage recovery, if an evaluator writes `oracle-marker` into `/data/oracle-marker` in `audit-store-0` and deletes that pod, a replacement with a different UID must become Ready within 90 seconds and keep the exact marker. In the same recovery window, `audit-headless` should return to exactly two Ready endpoint addresses and `audit-svc` should again serve the expected body for ordinal zero to an `access=audit` client.
