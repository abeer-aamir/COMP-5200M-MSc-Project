A small ledger endpoint needs durable content, restricted access, and a paused checker that validates the live Service rather than a copied setting. Keep everything in `medium-ledger-ns`.

Create an immutable ConfigMap called `ledger-seed`, containing only `index.html=ledger-version=v1\n`. Create PersistentVolumeClaim `ledger-data` with `ReadWriteOnce`, `volumeMode: Filesystem`, and a storage request of exactly 64Mi.

Run Deployment `ledger-web` with one replica and pod label `app=ledger-web`. Its pod mounts `ledger-seed` read-only at `/seed` and the `ledger-data` claim at `/data`. Use exactly one init container named `seed`, with `busybox:1.36.1`, running `sh -c "if [ ! -f /data/index.html ]; then cp /seed/index.html /data/index.html; fi"`. Its only main container is `web`, also using `busybox:1.36.1`; run `httpd -f -p 8080 -h /data`, expose named TCP port `http` on 8080, and use an HTTP readiness probe on `/` through that named port every five seconds. The pod must be Ready within 90 seconds. Configure the Deployment with strategy `Recreate`, `progressDeadlineSeconds: 120`, and `revisionHistoryLimit: 1`.

Expose it through ClusterIP Service `ledger-svc`, selecting `app=ledger-web`, with TCP port 80 targeting `http`. Before any storage mutation, a same-namespace client labelled `access=ledger` should receive exactly `ledger-version=v1` followed by a newline. NetworkPolicy `ledger-ingress` should select the ledger pod and allow TCP 8080 only from same-namespace pods labelled `access=ledger`, denying all other ingress to it.

Add ResourceQuota `ledger-quota` whose complete hard-limit set is exactly `requests.storage: "256Mi"`, `persistentvolumeclaims: "2"`, `pods: "6"`, and `services: "2"`.

Create a suspended CronJob named `ledger-check`, scheduled for `*/15 * * * *` with `Forbid` concurrency. Label its pod `access=ledger`, use one `busybox:1.36.1` container named `checker`, and run `sh -c "i=0; until body=$(wget -qO- http://ledger-svc); do i=$((i + 1)); [ \"$i\" -ge 10 ] && exit 1; sleep 2; done; test \"$body\" = ledger-version=v1 && echo ledger-check-ok"` with `restartPolicy: Never`. Before the storage mutation described below, a Job created from this CronJob must Complete within 60 seconds and log only `ledger-check-ok` followed by a newline.

An evaluator will then replace `/data/index.html` with exactly `ledger-version=v2\n` and delete the web pod. A replacement with a different UID must become Ready within 90 seconds and still serve the v2 content; the init container must not overwrite that existing file.
