A small ledger endpoint needs durable content, restricted access, and a paused scheduled check that validates the live service rather than a copied configuration value.

- Create a Namespace named `medium-ledger-ns`.
- In namespace `medium-ledger-ns`, create a ConfigMap named `ledger-seed` containing exactly one key, `index.html`, with value `ledger-version=v1` followed by a newline.
- In namespace `medium-ledger-ns`, create a PersistentVolumeClaim named `ledger-data` with `accessModes: ["ReadWriteOnce"]`, `volumeMode: Filesystem`, and a storage request of exactly `64Mi`.
- In namespace `medium-ledger-ns`, create a Deployment named `ledger-web` with exactly one replica and pod label `app=ledger-web`. Its pod must mount ConfigMap `ledger-seed` read-only at `/seed` and PVC `ledger-data` at `/data`. It must have exactly one init container named `seed` using `busybox:1.36.1` and `sh -c "if [ ! -f /data/index.html ]; then cp /seed/index.html /data/index.html; fi"`, and exactly one main container named `web` using `busybox:1.36.1`, command `httpd -f -p 8080 -h /data`, named TCP port `http` on 8080, and an HTTP readiness probe on path `/` and named port `http` with `periodSeconds: 5`. The pod must become Ready within 90 seconds. After an evaluator replaces `/data/index.html` with exactly `ledger-version=v2\n` and deletes the pod, a different-UID replacement must become Ready within 90 seconds and must still serve exactly `ledger-version=v2\n`; the init container must not overwrite the existing file.
- In namespace `medium-ledger-ns`, create a ClusterIP Service named `ledger-svc` selecting `app=ledger-web`, with TCP port 80 targeting named port `http`. Before evaluator mutation it must return exactly `ledger-version=v1` followed by a newline to an in-namespace pod labelled `access=ledger`.
- In namespace `medium-ledger-ns`, create a NetworkPolicy named `ledger-ingress` selecting `app=ledger-web`. It must allow ingress on TCP 8080 only from pods in the same namespace labelled `access=ledger`, with all other ingress to the selected pods denied.
- In namespace `medium-ledger-ns`, create a ResourceQuota named `ledger-quota` whose hard limits are exactly `requests.storage: "256Mi"`, `persistentvolumeclaims: "2"`, `pods: "6"`, and `services: "2"`.
- In namespace `medium-ledger-ns`, create a CronJob named `ledger-check` with schedule `*/15 * * * *`, `suspend: true`, and `concurrencyPolicy: Forbid`. Its pod template must have label `access=ledger`, use one container named `checker` with image `busybox:1.36.1`, and run `sh -c "i=0; until body=$(wget -qO- http://ledger-svc); do i=$((i + 1)); [ \"$i\" -ge 10 ] && exit 1; sleep 2; done; test \"$body\" = ledger-version=v1 && echo ledger-check-ok"` with `restartPolicy: Never`. Before any evaluator storage mutation, a Job created from this CronJob must reach Complete within 60 seconds and log exactly `ledger-check-ok` followed by a newline.
- Set ConfigMap `ledger-seed` to `immutable: true`.
- Configure Deployment `ledger-web` with strategy type `Recreate`, `progressDeadlineSeconds: 120`, and `revisionHistoryLimit: 1`.
