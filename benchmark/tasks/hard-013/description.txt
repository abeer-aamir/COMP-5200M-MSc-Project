Put a small source with two independent downstream views in `hard-fanout-ns`. Both views should follow the same source, but replacing one view must not disturb the other.

Mutable ConfigMap `fanout-page` contains only `index.html=source=v1\n`; immutable Opaque Secret `fanout-key` contains only `TOKEN=fanout-ok`. Deployment `fanout-source` has two replicas labelled `app=fanout-source` and `component=source`. Its one `busybox:1.36.1` container mounts the page at `/srv`, verifies the Secret token, serves named `source-http` at 8080, probes `/` every five seconds, disables API-token mounting and uses RollingUpdate with no unavailable pods, one surge and five ready seconds. Both replicas are Ready within 120 seconds. `fanout-source-svc` exposes TCP 8080 to that named port.

Deploy two replicas each of `fanout-alpha` and `fanout-beta`, labelled with their matching app and `component=alpha` or `component=beta`. Each one-container BusyBox pod mirrors a successful source response every two seconds using a five-second-bounded request, writes it into writable `/www`, removes the file on failure, and uses an HTTP readiness probe for `/` every five seconds with failure threshold two. Alpha writes `alpha:<body>` and serves it on named port `alpha-http` at 8081 while Service `fanout-alpha-svc` exposes port 80; beta writes `beta:<body>` and serves it on named port `beta-http` at 8082 while `fanout-beta-svc` exposes port 80. Both pairs should be Ready within 180 seconds.

Run every container as non-root UID/GID 1000 with `fsGroup: 1000`, no privilege escalation, read-only roots and all capabilities dropped; only view `/www` volumes are writable. Default-deny ingress and egress for all three components. Source 8080 is allowed only from alpha, beta or `access=fanout`; each view port only from `access=fanout`; and view egress only to source 8080 plus DNS UDP/TCP 53. Unlabelled clients reach none. Add one PDB per Deployment with its app selector, `minAvailable: 1`, and no `maxUnavailable`.

LimitRange `fanout-defaults` uses requests 20m CPU/32Mi and limits 200m CPU/128Mi. ResourceQuota `fanout-quota` has exactly 14 pods, five Services, 2 CPU/1Gi requests and 4 CPU/2Gi limits.

Changing the page to `source=v2\n` must update both source pods plus exact `alpha:source=v2\n` and `beta:source=v2\n` on both views within 180 seconds without generation or UID changes; restoring v1 gets another 180 seconds. Deleting the saved source Service must make all four views NotReady and remove both view endpoint sets within 90 seconds; exact restoration recovers endpoint counts 2/2/2 and v1 bodies within 180 seconds. Finally, deleting one Ready alpha after endpoint removal must still allow twelve exact one-second alpha calls, produce a new Ready UID within 90 seconds, and leave beta at two Ready endpoints throughout.
