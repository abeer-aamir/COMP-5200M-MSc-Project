Set up a node-local status registry in `hard-registry-ns`. A registry replica is only Ready when it can get the agent's exact response and use a narrow Kubernetes permission to observe that DaemonSet.

Mutable ConfigMap `node-page` contains only `index.html=node=v1\n`; immutable Opaque Secret `registry-key` contains only `TOKEN=registry-ok`. DaemonSet `node-status` uses labels `app=node-status` and `component=agent`, with no node selector or non-default tolerations. Its one `busybox:1.36.1` container mounts the page at `/srv`, serves named TCP port `agent-http` at 8090, probes `/` every five seconds, and has API-token mounting disabled. Exactly one agent should be Ready within 120 seconds. If it is deleted, a different-UID Ready agent serving the exact response must return within 120 seconds. Service `node-status-svc` selects it and exposes TCP 8090 to `agent-http`; `component=registry` clients get exactly `node=v1\n`.

Create token-enabled ServiceAccount `registry-reader`. Role `node-status-reader` has exactly two permissions: `get` on apps `daemonsets` named `node-status`, and `get` on `daemonsets/status` for the same name. RoleBinding `node-status-reader-binding` binds only that account.

Deployment `node-registry` has two replicas labelled `app=node-registry` and `component=registry`, using `registry-reader`. Its one `busybox:1.36.1` container reads `TOKEN` from the Secret and has an emptyDir at `/www`. Every three seconds it should require both a five-second-bounded authenticated API GET for `node-status` and the exact `node-status-svc` response before writing `registry:<body>` to `/www/index.html`; otherwise remove the file. Serve it on named TCP port `registry-http` at 8080 and probe `/` every five seconds with failure threshold two. Use RollingUpdate with no unavailable pods, one surge, five ready seconds and a 180-second progress deadline; both replicas must be Ready within 180 seconds. ClusterIP Service `node-registry-svc` exposes port 80 to that named port, and an `access=registry` client receives exactly `registry:node=v1\n`.

All agent and registry containers run as non-root UID/GID 1000 with `fsGroup: 1000`, no privilege escalation, read-only root filesystems and all capabilities dropped. Only registry `/www` is writable. Default-deny agent and registry ingress. Allow agent TCP 8090 only from `component=registry` or `access=registry`, and registry TCP 8080 only from `access=registry`. Unlabelled clients reach neither Service. Add `node-registry-pdb` with `minAvailable: 1`, selector `app=node-registry`, and no `maxUnavailable`.

Two other transitions must work. Deleting the saved RoleBinding should make both registry pods NotReady and remove all Ready registry endpoints within 90 seconds. Recreating the exact binding should restore one agent endpoint, two registry endpoints and the current body within 180 seconds; restoration must be attempted even after failure. Changing the ConfigMap page to `node=v2\n` should update the Ready agent and both Ready registry pods to their corresponding exact v2 responses within 180 seconds without controller generation or pod UID changes. Restoring v1 gets another 180 seconds and must also avoid rollout.
